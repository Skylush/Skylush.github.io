1. 部署概览

整体架构：

要点：

  • 录播姬容器只监听本机 127.0.0.1:2356，对外只暴露 Nginx 的 80/443。
  • 录像与配置文件统一放在容器的 /rec，对应宿主机的一个目录，不要放在系统盘。
  • 官方镜像：Docker Hub bililive/recorder，或 ghcr.io/bililiverecorder/bililiverecorder。
  • 默认 Web 端口为 2356。

准备工作：

  • 一台 Ubuntu 24.04 服务器，有 root / sudo 权限。
  • 一个已解析到服务器 IP 的域名（下文以 你的域名 代替）。
  • 提前规划好录像存放的磁盘。

3. 磁盘规划（单盘 / 多盘合并）

3.1 查看磁盘

找出空间大的数据盘及其挂载点（例如 /data、/data2 …）。

⚠️ 系统盘通常空间有限，录像文件增长很快，务必把录像目录放到数据盘。

3.2 确保磁盘开机自动挂载

在 /etc/fstab 里用 UUID 挂载，并加上 nofail：

不要写 /dev/sdb1 这类设备名，重启后顺序可能变化。

3.3 方案 A：只用一块盘

后面 compose 里直接挂载 /data/rec:/rec。

3.4 方案 B：多块盘合并成一个目录（mergerfs，推荐）

录播姬只有一个工作目录，用 mergerfs 把多块盘合并成一个，写满一块自动写下一块。

参数说明：

参数 含义
category.create=mfs 新文件写到剩余空间最多的盘
moveonenospc=true 写入时空间不足，自动尝试换盘
minfreespace=10G 某盘剩余不足 10G 时不再往它写
nofail 挂载失败不影响开机

注意：

  • 每个文件只会完整存在于某一块盘，一场很长的直播不会中途换盘。
  • 没有冗余，某块盘损坏会丢失这块盘上的文件。录播文件通常可以接受。
  • 日常操作统一通过 /mnt/pool，不要在底层盘上单独移动或删除同一个文件。

6. 申请 HTTPS 证书

certbot 会自动完成：

  • 签发证书并写入 Nginx 配置（443 块、HTTP 跳转 HTTPS）；
  • 配置定时任务，到期前自动续期。

验证：

证书申请失败：额度被用完（rate limit）

如果使用的是公共免费二级域名（很多人共用同一个主域名），可能会遇到：

这是共用主域名的额度被别人用完，不是你的配置问题。解决办法：

  1. 按报错里的时间点等待额度恢复后重试；
  2. 更推荐：改用你自己的域名，不和别人共用额度，续期也更稳。

换用其他 CA（如 ZeroSSL）也是一种思路，但订单有可能长时间处于 Pending 状态，建议优先使用自己的域名 + certbot。
失败后如留下空的证书文件，请清理后再重试：删除对应的空 .crt / .key 文件，并确认 Nginx 配置没有引用它们。

7. 防火墙与安全

只放行 80 和 443，不要对外开放 2356：

云厂商的安全组也同样只保留 22（建议限制来源）、80、443。

安全清单：

  • Web 管理界面已设置账号密码（basic auth）
  • 容器端口仅绑定 127.0.0.1
  • 全站 HTTPS
  • 密码使用随机强密码，且不外泄
  • 定期更新镜像和系统

证书签发之前，通过 http:// 登录会明文传输密码。需要提前使用时，可用 SSH 隧道：
ssh -L 2356:127.0.0.1:2356 root@服务器IP，然后本机浏览器访问 http://127.0.0.1:2356。

8. 开始录制与查看存储位置

8.1 添加房间

  1. 浏览器打开 https://你的域名，输入账号密码；
  2. 点击“添加房间”，输入 B 站直播间号；
  3. 开启该房间的“自动录制”。

8.2 逻辑位置与物理位置

  • 逻辑位置：/mnt/pool（容器内 /rec）。默认按房间建子目录，如 /mnt/pool/房间号-主播名/。
  • 物理位置：某一块盘的 rec 目录。

配置文件 config.json 也在 /mnt/pool 下（实际存放在某一块盘里）。

9. 录像转码为 MP4

录播姬录出来的是 .flv。在手机、剪辑软件、部分播放器里使用 .mp4 更方便。有两种做法，绝大多数情况用“封装转换”就够了。

方式 原理 速度 画质 CPU 占用 适用场景
A. 封装转换（remux） 只换容器，不重新编码（-c copy） 极快（秒到分钟级） 无损 很低 推荐，默认选择
B. 重新编码（x264） 重新压缩视频 慢 有损，可调 很高 需要缩小体积、或兼容老设备

9.1 安装 ffmpeg

9.2 单个文件转换

方式 A：封装转换（推荐）

  • -c copy：音视频流原样复制，不重新编码；
  • -fflags +genpts：重新生成时间戳，避免个别文件时间轴异常；
  • -movflags +faststart：把索引放到文件头，便于网络播放和快速打开。

方式 B：重新编码为 H.264 + AAC

  • -crf：数值越小画质越好、体积越大，常用 18–28；
  • -preset：ultrafast → veryslow，越慢压缩率越高；
  • 低配 VPS 上重新编码会很慢且占满 CPU，不建议在录制的同时做大批量编码。

如果录像本身的编码不被 MP4 容器支持，-c copy 会报错，这时再改用方式 B。

9.5 注意事项

  • 空间：转换会同时存在 flv 和 mp4。封装转换后体积基本和原文件相当，保留原文件会占用双倍空间，磁盘紧张时可在验证无误后使用 KEEP_SRC=0。
  • mergerfs：mp4 与源文件可能落在不同的物理盘上，属于正常现象，通过 /mnt/pool 访问不受影响。
  • 文件名：转换后的 mp4 与原 flv 同名同目录，只是扩展名不同。
  • 损坏的录像：如果录像因直播流异常而损坏，可先用录播姬自带的修复功能（工具箱）处理，再转 MP4。
  • 性能：低配机器优先使用封装转换；需要压缩体积时，建议在空闲时段做，或下载到本地电脑处理。

10. 日常维护

建议定期做的事：

  • df -h /mnt/pool：检查磁盘空间；
  • 备份 /mnt/pool/config.json（房间列表和设置）；
  • sudo certbot renew --dry-run：确认证书续期正常；

11. 常见问题排查

现象 可能原因 处理办法
curl -I 返回 405 HEAD 请求不被允许 用 GET 测试，不是故障
访问返回 401 未带账号密码 正常现象，输入账号密码
访问返回 502 容器没运行 / 端口不对 docker compose ps，检查 127.0.0.1:2356
重启后容器内 /rec 为空 mergerfs 比 Docker 启动晚 docker compose restart rec
/mnt/pool 容量不对 mergerfs 没挂上 sudo mount -a，检查 fstab
提示 fstab 已修改 systemd 缓存 sudo systemctl daemon-reload
容器写入权限不足 磁盘文件系统/权限问题 数据盘使用 ext4 或 xfs，检查目录权限
证书签发失败（额度用完） 共用的公共域名额度被占满 等待恢复，或改用自己的域名
证书文件为 0 字节 之前签发失败的残留 删除残留文件，并确认 Nginx 没引用
转 MP4 报错 编码不被 MP4 容器支持 改用 MODE=x264
转换后画面/声音不同步 原文件时间戳异常 保持 -fflags +genpts，必要时用重新编码

12. 附：只能录直播吗？点播视频怎么下载

录播姬只能录制 B 站直播间的直播，不能下载投稿视频（点播）。点播下载可以使用其他工具：

  • yt-dlp：通用下载工具，支持 B 站视频；
  • BBDown：专门针对 B 站的命令行下载器。
